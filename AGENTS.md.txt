# LifeInbox Repository Instructions

## Project

LifeInbox is a personal information inbox.

Its long-term product flow is:

Capture → Understand → Organize → Retrieve → Action

The product follows the principle:

Capture First, Organize Later.

## Architecture

Frontend:
- Vue 3
- Vite

Backend:
- Java 21
- Spring Boot 4.1
- MyBatis-Plus
- MySQL

Future AI service:
- Python
- FastAPI

Java is the source of truth for business data.

Python should be used for AI understanding and processing, not duplicate core business ownership.

## Core Model

All captured information should first enter the unified Inbox model.

The main entity is:

InboxItem

Do not create separate business models for TEXT, URL, IMAGE and FILE unless there is a clear need.

## Development Principles

- Read existing code before making changes.
- Prefer small, incremental features.
- Keep implementations simple and understandable.
- Do not introduce infrastructure without a real requirement.
- Do not refactor unrelated code.
- Preserve existing working behavior.
- Run relevant build/tests after modifications.
- Never claim verification that was not actually performed.
- Do not hardcode passwords, tokens or API keys.

## Product Direction

The project may gradually support:

- Text capture
- URL capture
- Files and images
- AI summaries and tags
- Semantic search
- Todo and deadline extraction
- Personal knowledge retrieval

These are roadmap directions, not requirements for every task.

Only implement features explicitly requested in the current task.
